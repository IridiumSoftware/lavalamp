### §9.5 — What this audit does NOT establish

- **It does not validate the security claims.** A0-A6 check
  internal consistency of spec / registry / code / docs.
  Whether the LavaLamp security primitive is actually secure
  against real adversaries is the *substance* of the
  spec entries; the audit checks the *bookkeeping*.
- **It does not catch code bugs.** CI runs the test suite;
  the audit doesn't re-test. A6 verifies that tests exist
  and run, not that tests cover all relevant cases.
- **It does not catch design errors.** A0 checks that
  CLAUDE.md describes observable practice; it doesn't
  evaluate whether the practice is correct. The
  synthesis-team review protocol (round 1, round 2,
  upcoming round 3) is the design-validation mechanism.

The audit's purpose is consistency / honesty across the
project's documentation and evidence layers. It complements
but doesn't replace the substantive validations: tests
(CI), benchmarks (on-demand + committed results), and
synthesis-team review (rounds 1-3+).
