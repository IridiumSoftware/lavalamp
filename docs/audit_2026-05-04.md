# Diagnostic Findings — 2026-05-04

Version: post-0.0.26 (no version bump; diagnostic capture only)

Per the lavalamp CLAUDE.md §Cross-audit protocol: this artefact
is shaped like a cross-audit findings document but covers a
*diagnostic* finding rather than a structural drift. The
`audit_YYYY-MM-DD.md` filename convention is reused; the content
is a benchmark-attempt postmortem.

**Trigger.** LL-020 Strategy 2 detection-power-vs-ε benchmark
(`src/julia/benchmark/ll020_strategy_2_detection_power.jl`) ran
to completion but produced an obviously-pathological result:
P(reject) = 1.000 across every (ε_DP, ε_A) cell except the
no-DP baseline. Even at ε_DP = 10 (the mildest privacy budget
in the sweep), the genuine device fails verification 100% of
the time.

Two questions arose: (a) did host-state contamination cause it
(e.g., laptop sleep during the run)? (b) if not, what did?

**Method.** Run the benchmark twice with no other system
changes; byte-compare the two result files. If identical, the
result is deterministic and host-state is ruled out as a
cause.

**Result: PASS on determinism; FAIL on implementation soundness.**

- Two consecutive runs of the benchmark produced byte-identical
  output (`diff` exit 0).
- Sleep / scheduler / thermal / clock-skew effects are ruled
  out as the cause of the pathological numbers.
- The fault lies in the implementation of
  `differentially_private_envelope` in
  `src/julia/src/Audit.jl`, exposed cleanly by the benchmark.

The implementation bug needs an architectural decision to fix
(three options laid out in §3 below). LL-020's status stays
`:argued` per CLAUDE.md status-honesty discipline; the
benchmark currently provides *negative* evidence about
Strategy 2's implementation and does not close the entry to
`:benchmarked`-tier evidence.

This document is not a fix; it is a captured-state-as-of-the-
finding so the next session resumes from a known position
rather than from a contaminated context.

## §1 — Computational basis

**Benchmark script.** `src/julia/benchmark/ll020_strategy_2_detection_power.jl`
(landed in this commit). Configuration mirrors the P3-bound
benchmark for direct comparability:

- Lorenz-96 N=20, F=8, single coupling channel b=ones(N),
  α=1.0, constant_stream(1.0).
- Calibration: n_trials = 10, N_benettin = 1200, Δt = 0.05,
  Ttr = 200.0; CALIBRATION_SEED = 101.
- Verifier: `verify(λs, env_pub; k=5)`.
- Adversary: synthetic_adversary with isotropic unit-vector ×
  ε_A; ε_A grid {0.0, 0.5, 1.0, 1.5, 2.0, 3.0}; 10 trials per
  ε_A.
- DP grid: ε_DP ∈ {0.3, 1.0, 3.0, 10.0}; δ = 1e-6;
  sensitivity = 0.1; 5 DP-realizations per ε_DP.
- Trajectory computation shared across (ε_DP, DP-realization)
  cells (only the published envelope changes per cell, not
  the adversary's λs).

**Reproducibility.** Deterministic via fixed RNG seeds. The
DP-realization seeds are derived from a fixed base
(`Xoshiro(4000 + round(ε_DP·10) + r·1000)`) so the same
ε_DP value produces the same noise draws across runs.

**Run host.** Apple Silicon laptop. macOS. Julia 1.12,
DifferentialEquations 7.17, DynamicalSystems 3.6.7,
StaticArrays 1.9.18 (per `Project.toml` / `Manifest.toml`).
Wall clock ~15 s per run (calibration ~4 s + 60 trajectory
computations ~8 s + verify checks ~1 s).

**Result file.** `src/julia/benchmark/results/ll020_strategy_2_detection_power_lorenz96.txt`.

The two runs produced byte-identical output. Combined with the

was a loose-tolerance regime (±15% on λ₁, ±25% on h_KS) and
did not test bit-for-bit determinism.

### §2.2 — Implementation bug in `differentially_private_envelope` (FAIL)

The current implementation (`src/julia/src/Audit.jl:381–409`):

```julia
σ_DP = sensitivity * sqrt(2 * log(1.25 / δ)) / ε
spectrum_pub = env.spectrum .+ σ_DP .* randn(rng, n)
σ_pub = env.σ .+ σ_DP .* randn(rng, n)
σ_pub = max.(σ_pub, 1e-10)
```

**The pathology.** With `env.σ` calibrated at the prototype's
config (mean 0.0788, max 0.1944, min 0.0155) and `σ_DP` at
0.0530 (ε_DP = 10, the mildest privacy budget tested):

- `σ_DP * randn` is symmetric-Gaussian with magnitude ~0.053
  per draw.
- For the smallest σ component (`env.σ_min = 0.0155`), the
  noise pushes `σ_pub` negative roughly 77 % of the time
  (P(|Z| > 0.293) under N(0,1)).
- The data-independent floor at 1e-10 then clamps the
  affected component to ~0.
- The verifier's threshold for that component is
  `k · σ_pub ≈ 5e-10` — effectively zero.
- *Any* non-exact match on that component triggers rejection.

With 20 components and n=10 trials per cell, the probability
that at least one component triggers a hard-rejection on
every trial is essentially 1. The genuine device is rejected
100 % of the time.

**The implementation contradicts its own docstring.** The
current docstring (`Audit.jl:357–363`) says:

> The verifier using the perturbed envelope has correspondingly
> *wider* threshold tolerances (k · σ_perturbed vs k · σ_original
> where σ_perturbed > σ_original due to the added noise), so
> detection power decreases as ε decreases.

This claim — "σ_perturbed > σ_original due to the added noise"
— is **false** for the current implementation. Symmetric
additive Gaussian noise is just as likely to shrink σ as to
inflate it. The floor at 1e-10 then catastrophically fails
*either* direction (shrunk σ becomes near-zero threshold;
amplified σ becomes wider threshold).

The 23 existing test assertions in `src/julia/test/runtests.jl`
pass because they exercise the σ_DP formula, the metadata
recording, the argument validation, and the reproducibility
under fixed seeds — but none of them check that the resulting
envelope passes verification against a genuine device. The
benchmark is the first artefact that exercises end-to-end
operational correctness.

### §2.3 — Genuine-device rejection breakdown

For each ε_DP in the sweep:

| ε_DP   | σ_DP   | σ_DP / σ_min | P(genuine reject) |
|--------|--------|--------------|-------------------|
| 10.00  | 0.0530 | 3.4×         | 1.000             |
| 3.00   | 0.1766 | 11.4×        | 1.000             |
| 1.00   | 0.5299 | 34.2×        | 1.000             |
| 0.30   | 1.7663 | 113.9×       | 1.000             |
| no DP  | —      | —            | 0.100             |

The σ_DP / σ_min ratio is the single useful predictor: when
σ_DP exceeds σ_min by even 3×, the probability that the
smallest-σ component goes near-zero on the published
envelope approaches 1. The prototype's calibration regime
(σ_min ≈ 0.0155 from n=10 trials at N_benettin=1200) is
intrinsically narrow, which makes the σ floor a hard
operational ceiling on Strategy 2's tolerance.

The no-DP baseline FPR of 0.100 is the expected per-deployment
false-positive floor at k=5 / n_trials=10 (matches P3-bound
empirical FPR floor).

## §3 — Architectural decision pending

The bug needs a fix; the fix is a design choice the project
should weigh in on rather than an automatic refactor. Three
options:

### Option A — Variance-convolution mechanism (recommended)

Replace the σ perturbation with a deterministic variance-
convolution form:

```julia
σ_pub = sqrt.(env.σ .^ 2 .+ σ_DP^2)
```

This:

- Always produces `σ_pub ≥ env.σ` per component (no
  negativity, no floor).
- Reflects the *expected* convolved variance of the residual
  when comparing genuine λs against a DP-perturbed spectrum:
  `Var(genuine_residual + DP_shift) = σ_true² + σ_DP²`.
- Matches the docstring's stated "wider tolerances" intent.
- **Trade-off.** σ is no longer DP-protected (`σ_pub` is a
  deterministic function of `env.σ`, leaking a lower bound).
  Only the spectrum is DP. For a calibration-confidentiality
  strategy this is honest: σ is calibration *confidence*
  metadata, less sensitive than the spectrum itself.

Operationally cleanest. Documented as an explicit Strategy 2
design refinement, not silently swapped.

### Option B — Document negative result, leave bug

Treat this finding as a P3-Nyq-style negative result:
Strategy 2's current implementation has a calibration regime
where DP at any reasonable ε is operationally broken at the
prototype's k=5 / N=20 / n_trials=10 config. LL-020 stays
`:argued`; the benchmark file is committed as audit-trail
evidence; the implementation issue becomes round-3 input.

Honest but leaves a known bug in the codebase. Not
recommended unless the user prefers to defer the fix entirely
to round-3.

### Option C — Tune sensitivity / k around the bug

Increase `sensitivity` parameter from 0.1 to ≫1.0, or drop
`k` to 1.0 to widen tolerance without fixing the floor logic.
**Not recommended.** This would be papering over the bug; the
underlying mechanism (symmetric noise on σ + floor) is wrong
by design and would re-emerge at any other calibration
config.

### Recommendation

Option A. The benchmark caught the bug cleanly — that is
exactly what benchmarks are for — and the fix matches the
design intent already documented in the docstring. Round-3 has
plenty of other open questions that deserve attention more
than a known-resolvable implementation bug.

## §4 — Project-discipline implication

The benchmark exposed a bug that 23 existing test assertions
missed. The gap: tests checked properties of the
`differentially_private_envelope` *function* (formula, metadata,
reproducibility) but did not check that the *output* of the
function preserved verification-correctness against a genuine
device. End-to-end operational correctness is in the benchmark,
not in the unit tests.

This is a generalisable lesson for the test/benchmark split in
the prototype:

- Unit tests should cover function-level invariants
  (formulas, types, argument validation, reproducibility).
- Benchmarks should cover system-level invariants
  (genuine-device acceptance, adversary detection, end-to-end
  correctness).
- A function that passes unit tests but fails benchmarks is
  still broken; the benchmark is part of the test surface.

The CLAUDE.md addendum landing in this commit captures the
narrower discipline rule: brittle-precision benchmarks (where
the regime is sensitive to per-component σ-scale effects)
should always include a determinism check on the first run, so
that pathological results can be cleanly attributed to the
implementation rather than to host-state contamination.
